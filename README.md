# 电商购物机器人（中文版）

一个基于 **python-telegram-bot (v22+)** 的功能完整的 Telegram 电商购物机器人。支持多规格商品、购物车、优惠券、卡转账付款审核、邀请返佣、客服工单，以及完整的管理后台。

> 由 **培哥** 制作并维护。

## 功能特性

**顾客端**
- 🛍 商品目录：按分类浏览，商品支持多规格（颜色/尺码/型号），可带图片。
- 🛒 购物车：增删商品、使用优惠券、查看合计与折后价。
- ✅ 下单：填写姓名/电话/地址，下单时校验库存并扣减。
- 💳 卡转账付款：显示收款卡 → 上传回执图 → 管理员确认。
- 🧾 我的订单：查看历史订单、状态、明细。
- 👥 邀请返佣：专属邀请链接，下线付款后按比例返佣到钱包。
- 📞 客服工单：提交问题，管理员可回复。

**管理后台**
- 分类 / 商品 / 规格的添加与商品下架。
- 订单管理（确认 / 发货 / 取消，自动通知买家）。
- 支付管理（确认 / 拒绝回执）。
- 优惠券管理（百分比 / 固定额、最低订单、过期时间、使用次数）。
- 客服工单回复与关闭。
- 销售统计、用户列表。

## 安装与运行

```bash
pip install "python-telegram-bot>=22.7" --upgrade
python bot.py
```

## 配置

编辑 `bot.py` 顶部：

| 常量 | 说明 |
|------|------|
| `BOT_TOKEN` | BotFather 的机器人 Token |
| `ADMIN_IDS` | 管理员数字ID列表（用 @userinfobot 获取） |
| `CURRENCY` | 货币单位，默认「元」 |
| `REFERRAL_BONUS_PERCENT` | 邀请返佣百分比 |
| `PAYMENT_CARD_NUMBER` | 收款卡号 |

## 已修复的问题

原版存在几个会导致功能失效或资金错误的问题，本版已全部修复：

- **按钮无法生成（致命）**：原版给 `InlineKeyboardButton` 传了 `style=` 参数，但标准 python-telegram-bot 不支持该参数，会直接抛 `TypeError`，导致大量按钮根本发不出来。已全部移除。
- **超卖 / 库存竞态**：原版下单时先算价再扣库存、且库存校验与扣减分离，并发下单会超卖。已改为在单个 `BEGIN IMMEDIATE` 事务内「校验库存→扣库存→写单→清车」，杜绝超卖。
- **优惠券在下单函数里另开连接**：原版在事务外用裸连接更新券使用次数，异常时不回滚。已并入同一事务。
- **返佣可重复发放**：原版确认付款没有幂等保护，重复点「确认」会重复发返佣。已新增 `referral_awarded` 标记 + 原子领取，杜绝重复。
- **重复确认付款**：新增 `payment.status != 'pending'` 判断，已处理过的付款不能再次确认/拒绝。
- **图片消息编辑报错**：确认付款的消息本身是图片，原版用 `edit_message_text` 会失败。已改为自动区分图片/文本编辑。
- **上架商品未扣付款状态**：上传回执后订单支付状态未变，已置为「等待确认回执」。
- **输入校验**：价格/库存/金额等负数与非法输入已拦截。
- **全面中文化**：界面、提示、状态、货币（原「تومان」→「元」）。

## 优点

- **功能完整**：多规格、购物车、优惠券、返佣、工单、后台一应俱全，接近可直接运营。
- **基于 ConversationHandler**：多步流程（下单、加规格、建券）结构清晰。
- **外键 + 索引**：数据库设计规范，关联删除与查询性能都考虑到了。

## 已知限制与建议

- **人工核账**：付款靠管理员肉眼核对回执图，存在假回执风险。
- **取消订单不回滚库存/退款**：管理员取消订单时，未自动把库存加回、未退款，需后续完善。
- **`context.user_data` 在内存**：重启后进行中的多步会话会丢失。
- **无并发/限流**：`run_polling` 单实例，适合中小规模。
- **合规提示**：请仅用于合法商品销售，遵守所在地区的法律法规。
